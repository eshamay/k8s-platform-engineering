# Mechanics and accuracy pass gap dispositions

This page triages the 43 mechanics gaps (clusters m1 to m7) that the mechanics-and-accuracy pass researched, and it records what the four b1 accuracy rechecks confirmed, corrected, or left caveated. It is a recommendation only. No gap was closed and `open-knowledge-gaps.md` was not edited, because only the user closes gaps (through `sticki-gaps`). Each row's evidence comes from the "Possible resolution" note the ingest wrote under the gap, checked against the source pages named in the row. Of the 43 gaps, 14 are resolved-candidate, 26 are partial, 3 are still-open, and none is needs-different-source on its own, although several partial rows carry an unreadable-source remainder (see the manual-fetch table below).

## What changed, what is missing, and where to go next

The pass changed the wiki mostly through corrections and added source-level detail, not through new open questions. The b1 rechecks corrected pages in place on Argo CD polling and sharding, the Crossplane poll and reconcile-rate values, kro's released-version defaults, Flux's jitter, and the Mutating Admission Policy and StorageVersionMigration stages. They marked two pages contradicted (the controller-runtime read-your-writes example and the Crossplane concurrency comparison). The m1 to m7 dossiers added findings for finalizer names, ownership and garbage collection, status conditions, server-side apply, caches, admission, and operators. Cluster API v1.15.0 final does not exist, so every v1.15 statement remains a release-candidate claim.

What could not be found is mostly absence and unreadable material. No Crossplane maintainer reply exists on issue 7801, no documentation covers a namespaced managed resource when a namespace is deleted while the provider is down, no KEP covers cross-namespace ownership, no official CRD count limit exists, no selection criteria for operator frameworks were found, and no source ranks observedGeneration placement or condition polarity. The remaining reads are gated on unreadable pages: the Config Connector docs for field managers, the Crossplane performance guide path, the KREP documents, the Joe Beda book attribution, and the conference talks and video-hosted incident reports.

The user is best placed to close the 14 resolved-candidate gaps first, starting with the ones whose remainder is a single named detail: the Argo CD and Flux finalizer gaps, Cluster API issue 1514, informer resync, CEL cost limits, the conversion webhook and garbage collection gap, and Config Connector conflict handling. The three still-open gaps are decisions the user can make without more research. "Best default conflict policy" and "criteria for choosing an operator framework" can be closed as "no source answers this; see the options pages", and the provider-down namespace case needs a cluster experiment rather than more reading. Among the partial gaps, the observedGeneration placement and condition polarity gaps are the nearest to closure, because the evidence is complete and only a normative ranking is missing. The user decides whether to close them.
