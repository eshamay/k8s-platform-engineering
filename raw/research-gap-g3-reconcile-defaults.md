# Research dossier: gap cluster g3-reconcile-defaults

Research date: 2026-11-26

## Overview

This pass read primary sources only: the live Flux, Argo CD, ACK, and Config Connector documentation, plus raw source files and docs fetched with `gh api` at named tags or the default branch. Quotes are verbatim and short. Where a source is the repository default branch, the entry says "default branch as of 2026-11-26" because no tag was pinned for it.

The Flux conflict is a real inconsistency inside Flux's own docs, not a version difference. The Flux concepts page says a Kustomization "runs every five minutes by default". The Kustomization API reference, the CRD Go type, and the HelmRelease reference all mark `.spec.interval` as required, so no controller-side default exists. The only defaults found are the CLI's: `flux create` has a global `--interval` default of 1 minute. The "60 seconds" figure is a "should" (a recommended minimum) in prose. The CRD type carries only a duration-format regex, not a minimum. So the five-minute figure is best treated as documentation shorthand that matches the 5m used in most examples.

Argo CD changed its default between v2.14 and v3.0. Through v2.14.0, `argocd-cm` documented `timeout.reconciliation: 180s` with jitter 0 (jitter was absent from v2.9.0 and documented as 0 from v2.10.0). From v3.0.0 through v3.6.0 it is `120s` plus `timeout.reconciliation.jitter: 60s`. The v3.0.0 FAQ calls this "default maximum polling interval ... 3 minutes (120 seconds + 60 seconds jitter)". The wording now reads as the old 3-minute figure, but the mechanism differs: the base is 2 minutes and the jitter is random.

Crossplane, ACK, Cluster API, and Config Connector each use a different notion of "interval". Crossplane's poll interval is per-resource and defaults to 1 minute in crossplane-runtime and in Crossplane core. A Upjet-based provider (provider-upjet-aws) overrides it to 10 minutes, with a 1-hour controller-runtime sync period. ACK defaults to 10 hours after `ResourceSynced`. Cluster API's `--sync-period` is 10 minutes, but it is a cache resync, not a cloud-drift poll. Config Connector's mean reconcile period is 10 minutes by constant, with per-kind overrides and a jitter that spreads actual requeues between 0.5x and 1.5x of the mean.

## Gap: Flux default reconcile interval and drift-detection wording

Findings: The two pages do not describe the same thing. The concepts page states a default; the API reference says the field is required with a recommended minimum, and the CRD enforces neither a default nor a minimum. Nothing read states a controller-side default. The `flux create` CLI default is 1 minute for the global `--interval` flag. The example snippets mostly use 5m, 10m, or 60m. Drift correction occurs on the interval: the reference says reconciliation applies the Kustomization "correcting any existing drift". The ten-minute drift wording in the wiki is an example from a bullet list, not a default. A guide example uses `60m0s` with the comment "detect drift and undo kubectl edits every hour". Jitter can be configured in the controller to spread the interval; its value was not read.

## Gap: Argo CD default reconcile interval across versions

Findings: Default `timeout.reconciliation` was 180s through the v2.x line sampled (v2.5.0, v2.6.0, v2.7.0, v2.8.0, v2.9.0, v2.10.0, v2.11.0, v2.12.0, v2.13.0, v2.14.0). The `timeout.reconciliation.jitter` key first appears in the sampled `argocd-cm.yaml` at v2.10.0 (absent at v2.9.0) with default 0, and is documented as "defaults to 0" in v2.13.0. From v3.0.0 the default is 120s with jitter 60s; this holds in every later tag sampled (v3.1.0, v3.2.0, v3.3.0, v3.5.0, v3.6.0). The change is visible in both the manifest example and the application controller flag default (`defaultAppResyncPeriod` 180 in v2.14.0, 120 in v3.6.0, plus `defaultAppResyncPeriodJitter` 60). Effective polling is therefore between 120 and 180 seconds in v3.x, versus a flat 180 in v2.x. v2.0.0 `argocd-cm.yaml` did not contain the string `timeout.reconciliation` in the path checked. I did not find the v3.0 upgrade notes or PR that explains the change. Recent merged work: a title-only record of a 2026-07-31 PR treating `timeout.reconciliation=0` as disabled soft expiry.

## Gap: Reconcile defaults for Crossplane, ACK, and Cluster API

Findings: Crossplane's managed-resource reconciler has `defaultPollInterval = 1 * time.Minute` and a 30-second creation grace period. Crossplane core exposes `--poll-interval` default 1m, and a minimum per-resource poll interval of 1s. Providers built on Upjet override the poll interval: provider-upjet-aws S3 sets `--poll` default 10m, `--sync` 1h, and `--max-reconcile-rate` 100, with a poll jitter of 5% of the interval. A design one-pager for per-resource overrides through a `crossplane.io/poll-interval` annotation is marked "Draft", but the annotation is implemented in code (core `--min-poll-interval` at v2.4.4 and main; crossplane-runtime `AnnotationKeyPollInterval`) [corrected in verification: earlier text said it was not shipped]. ACK's default drift check is 10 hours after `ResourceSynced = true`, overridable per controller (`reconcile.defaultResyncPeriod`, seconds) or per kind (`reconcile.resourceResyncPeriods`). Cluster API's core controller flag `--sync-period` defaults to 10 minutes, described as the minimum interval at which watched resources are reconciled. That is a cache resync and not an infrastructure poll, and no per-resource drift period was found for it.

## Gap: Config Connector reconcile interval and drift cadence

Findings: The Google docs page "Reconciliation strategy" says each resource reconciles on every update and "after a jitter period with an average based on the preconfigured default interval", and points to a per-resource reference field named "Config Connector Default Average Reconcile Interval In Seconds". It does not state one number. In source, the global fallback constant `MeanReconcileReenqueuePeriod` is 10 minutes (`k8s-config-connector` default branch, release tag v1.162.0 seen). Resolution order in `reconciliationinterval.go`: Terraform servicemapping value, DCL metadata value, IAM kind constants (IAMPolicy reconcile interval is `10 * time.Minute`), else the 10-minute default. The annotation `cnrm.cloud.google.com/reconcile-interval-in-seconds` overrides it per resource. Jitter code returns `wait.Jitter(mean/2, 2.0)`, which spreads requeues between half and one and a half times the mean, so the default 10-minute mean means 5 to 15 minutes. Setting the annotation to 0 disables drift correction for that resource and the docs say this is irreversible without a spec edit or abandon-and-recreate. On errors the retry is exponential backoff capped at 120 seconds, configurable only on direct-controller resources. I did not retrieve the per-kind interval values from Terraform servicemapping or DCL metadata, so whether direct, TF, and DCL controllers differ by default stays open.
